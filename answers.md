# задание 1.1

результаты проверки `parseInt()`:

```js
parseInt(null, 10)        // NaN
parseInt(undefined, 10)   // NaN
parseInt('', 10)          // NaN
parseInt('   ', 10)       // NaN
parseInt('42', 10)        // 42
parseInt('  42  ', 10)    // 42
parseInt('42abc', 10)     // 42
parseInt('abc42', 10)     // NaN
parseInt('3.9', 10)       // 3
parseInt('-5', 10)        // -5
```

результаты проверки `Number()`:

```js
Number(null)      // 0
Number('')        // 0
Number('42abc')   // NaN
+null             // 0
```

отдельный случай:

```js
parseInt(null, 36) // 1112745
```

`parseInt()` сначала превращает `null` в строку `'null'`.

в обычной десятичной системе буквы не подходят, поэтому получается `NaN`.

но в 36-ричной системе можно использовать цифры `0-9` и буквы `a-z`. поэтому буквы из слова `'null'` считаются допустимыми символами, и `parseInt()` может превратить их в число.

---

## 1. что возвращает `parseInt(null, 10)` и почему?

`parseInt(null, 10)` возвращает `NaN`.

сначала `parseInt` превращает `null` в строку `'null'`. потом пытается прочитать её как обычное число, но буквы в десятичной системе не подходят, поэтому получается `NaN`.

---

## 2. почему `parseInt(null, 36)` дает число, а не `NaN`?

сначала `null` тоже превращается в строку `'null'`.

в 36-ричной системе можно использовать не только цифры, но и буквы. поэтому буквы из слова `'null'` можно прочитать как число.

---

## 3. в чем разница между `parseInt('42abc')` и `Number('42abc')`?

`parseInt('42abc', 10)` вернет `42`, потому что он берет число с начала строки и останавливается на буквах.

`Number('42abc')` вернет `NaN`, потому что он пытается преобразовать всю строку целиком. `parseInt` можно использовать, например, чтобы получить `42` из `'42px'`, а `Number` удобнее для проверки обычного ввода пользователя.

---

## 4. почему нельзя просто использовать `if (userGuess == randomNumber)`?

`prompt` возвращает строку, а `randomNumber` — число. при `==` javascript сам преобразует типы, например строка `'5'` станет числом `5` и сравнение даст `true`.

из-за этого мы не контролируем ввод пользователя отдельно. лучше сначала проверить и преобразовать ввод в число, а потом сравнивать через `===`.

---

## 5. почему `Number.isNaN(x)` лучше, чем `x === NaN`?

`NaN` не равен даже самому себе.

```js
NaN === NaN // false
```

поэтому через `x === NaN` проверить его нельзя. для этого есть специальная проверка `Number.isNaN(x)`.

---

## 6. что вернет `-7 % 2`?

`-7 % 2` вернет `-1`, потому что в javascript остаток сохраняет знак первого числа.

поэтому проверка:

```js
n % 2 === 1
```

не сработает для отрицательных нечетных чисел. лучше написать:

```js
n % 2 !== 0
```

---

## 7. что делают `break` и `continue`?

`continue` пропускает текущий шаг цикла и переходит к следующему. в задаче с деньгами он пропускает номинал, если его количество равно `0`.

`break` полностью останавливает цикл, когда остаток уже равен `0`. 

если поставить `break` вместо `continue`, цикл остановится на первом неподходящем номинале. если поставить `continue` вместо `break`, цикл будет продолжаться даже когда остаток уже стал `0`.

---

## какой вариант проверки ввода я бы оставила в проде?

я бы оставила вариант через `Number()`, потому что он проверяет всю строку целиком.

например, `Number('4.7')` вернет `4.7`, а `parseInt('4.7', 10)` вернет `4`. поэтому через `Number()` проще правильно проверять пользовательский ввод.
